# Лира 2.12.1 — комната общения

Говорящий 2D-портрет в браузере. Для базового запуска нужен только Python 3.8+. Без подключённой модели работает демо с ограниченным набором реплик.

## Запуск

1. Откройте терминал в корне репозитория — там, где находится `server.py`. Если скачали архив, сначала распакуйте его.
2. Выполните `python server.py` (на Windows также `py server.py`).
3. Откройте http://localhost:8000 в Chrome. Чтобы проверить анимацию и озвучку без микрофона, нажмите «Расскажи о себе».

## Камера: лицо и вопросы по кадру

На компьютере с камерой откройте **http://localhost:8000** в отдельной вкладке. В разделе «Камера» нажмите «Включить камеру». Автостарта нет. Видеопоток служит только для предпросмотра; приложение не пишет видео. Микрофон не запрашивается этим переключателем. Закрытие панели, скрытие вкладки или «Выключить камеру» останавливает видеодорожку. Если macOS отказала в доступе, проверьте разрешения браузера для сайта и **Системные настройки → Конфиденциальность и безопасность → Камера**.

**«Ты меня узнаёшь?»** Посмотрите прямо в камеру, убедитесь, что в кадре только вы, и нажмите «Запомнить моё лицо». После подтверждения сохраняется только числовой шаблон (128 значений) в localStorage. В другом браузере/по другому адресу нужен новый образец. Лира сравнивает по запросу, никого не ищет по внешней базе. Образец можно удалить кнопкой «Удалить образец лица». Это биометрические данные без шифрования; не используйте на общем профиле браузера. Это не проверка личности и не защита входа: возможны ошибки, распознавание по фотографии и сходство с другим человеком. Детектор, ориентиры и эмбеддинг face-api.js 0.22.2 (Vincent Mühler) включены в `assets/face/`, лицензия в `licenses/face-api-LICENSE.txt`. Дополнительные Python-пакеты для лица не нужны.

**«Что ты видишь?»** Установите и запустите Ollama на том же компьютере, выберите модель в панели «Камера» и скачайте её: `ollama pull gemma3:4b` или `ollama pull lfm3-omni`. Для LFM3-Omni на macOS нужна Ollama 0.40.12 или новее (https://huggingface.co/LiquidAI/LFM3-Omni-2B-GGUF). Выбор сохраняется в этом браузере. Выбранная в настройках модель обычного чата не меняется. По нажатию «Спросить по кадру» один уменьшенный JPEG и вопрос поступают в выбранную модель по `http://127.0.0.1:11434`. Адрес облачного API и переменная OLLAMA_URL для кадров не используются. История чата и шаблон лица модели зрения не передаются. Кадры не сохраняются приложением; сохраняются тексты вопросов и ответов в истории браузера. Реплики с камеры не добавляются в память фактов или последующий контекст текстовой модели. Уже переданный кадр нельзя отозвать выключением камеры. Ответ может ошибаться, особенно при плохом освещении и мелких деталях.

Можно писать и говорить «Лира, что ты видишь?» / «Ты меня узнаёшь?» при включённой камере. Произвольный вопрос вроде «Какого цвета кружка?» вводите в **поле вопроса по кадру**, чтобы Лира не приняла его за обычный чат. Для голосовых команд с полностью локальной обработкой используйте Vosk, а не облачный сервис браузера. Не снимайте других людей без их согласия. В удалённом предпросмотре доступ к анализу отключён.

## Модули: кнопка «Модули» и отдельные папки

Ядро Лиры остаётся маленьким: дополнительные режимы лежат в `modules/` и подключаются кнопкой **Модули** в шапке.

- Каждый модуль — своя папка с `module.json` (название, описание, страница) и, если нужно, `backend.py` с функцией `handle(action, data)`. Сервер находит модули сам: положили папку — модуль появился в списке.
- Включённый модуль открывается по `/modules/<id>/` и получает собственный адрес API `/api/<id>`; выключенный не отдаёт ни страницу (404), ни данные (403), а ярлык исчезает из шапки.
- Переключатели хранятся в `data/modules.json`. Исходники `*.py` наружу не отдаются, выход за папку модуля запрещён.
- Первый модуль — **ИИ-вахтёр** (`modules/vakhta/`): проходная с распознаванием лиц. Описание, настройки, вебхук двери и требования к биометрии — в [VAKHTA.md](VAKHTA.md).
- Как написать свой модуль: [modules/README.md](modules/README.md). Модули выполняются с правами сервера, песочницы нет — ставьте только доверенный код.

## ИИ-вахтёр: узнаёт жильцов и говорит у двери

**Модули → ИИ-вахтёр → Открыть** (адрес `/modules/vakhta/`, кнопка-ярлык **Вахтёр** появляется в шапке). Отдельный модуль для подъезда: вахтёр смотрит в камеру, сравнивает лицо с реестром жильцов и говорит вслух.

- Свой жилец — «Здравствуйте, Иван Петров! Проходите, пожалуйста.»
- Чужой — «Здравствуйте! Вы не из нашего дома. Зачем пришли?» Дальше слушает ответ (Vosk локально или клавиатура). Назвал квартиру — «Понятно, вы в квартиру 42. Секунду, сообщаю жильцам», дверь сама не открывается. Молчит или грубит — «Я не могу вас пропустить. Уходите, пожалуйста.»
- Гость из списка «его ждут» и нежелательный посетитель — отдельные роли и фразы.
- Реестр живёт на сервере: для распознавания сохраняются только числовые шаблоны лица (128 чисел на кадр). Рядом может лежать миниатюра лица 240×240 для карточки в редакторе жильцов — её можно удалить кнопкой «Убрать». Порог строгости, PIN администратора, журнал проходов, вебхук для реле двери, запуск в режиме киоска и требования к биометрическим данным — в [VAKHTA.md](VAKHTA.md).

Без камеры режим можно проверить кнопками **Демо-сценарии** и **Проверить по фото**.

## Свой голос · локальный синтез

**Настройки → Голос → Свой голос · локальный XTTS-v2**. Можно загрузить готовую голосовую запись и выбрать отрывок. Синтез доступен после отдельной [установки XTTS-v2](XTTS.md). Без неё Лира по-прежнему работает с прежними голосами.

## Голосовая активация «Лира»

Нажмите **Включить «Лира»** под кнопкой микрофона и разрешите доступ к нему. Когда появится «Микрофон включён», скажите **«Лира, который час?»** и сделайте паузу. Можно сначала сказать только «Лира», дождаться подсказки и произнести короткий вопрос в течение восьми секунд. В чат попадает вопрос, без обращения. Настройки проверки распознанного текста действуют как и при ручном вводе.

В ожидании микрофон **уже включён**: фоновый звук распознаётся локальным Vosk в браузере. Режим не записывает аудиофайлы и не сохраняет фоновую расшифровку. Совпадение проверяется в начале завершённой фразы; это не идентификация говорящего, поэтому на слово «Лира» может отреагировать и речь другого человека. Распознанный запрос после активации обрабатывается как обычное сообщение выбранным движком. На медленном устройстве первая загрузка модели или распознавание могут занять время.

На время ответа, ручного ввода, непустого черновика и открытых окон настроек/истории ожидание приостанавливается. **Выключить «Лира»** прекращает захват для активации. После скрытия вкладки или перезагрузки режим нужно включить заново. Для доступа к микрофону используйте отдельную вкладку с `localhost` или HTTPS. Ручной режим по кнопке или пробелу по-прежнему доступен.

## Что я помню — факты вместо карточек

По принципу [AI-companion](https://github.com/Eldar1717/AI-companion/blob/main/backend/models/memory.py) память Лиры — обычные текстовые утверждения, а не каталог людей. В SQLite (`data/memory.db` на компьютере с Python-сервером) лежат долгосрочные факты. Последние сообщения и интерфейс истории остались в браузере. SQLite входит в Python. Для памяти не нужна векторная база, дополнительная модель или Telegram.

- «Запомни: у моего друга Антона кот Барсик» → одна запись дословно, без регистрации Антона. «Я работаю в библиотеке», «Меня зовут Алина», «Мне нравится джаз» также распознаются по началу утверждения. Это правила для части русских фраз, а не анализ всех биографических подробностей. Для гарантированного добавления начните с «Запомни:». Догадки из ответов модели не сохраняются как факты.
- «Что ты обо мне помнишь?» → количество записей и несколько последних. **Настройки → Память → Что я помню**: весь список, поиск, добавление, исправление, удаление. Дубликаты с тем же текстом не множатся. Если факт устарел, исправьте его; смысловые противоречия автоматически не сливаются.
- Для свободного диалога выберите **Ollama → llama3.1:8b**. Включите «Использовать факты в ответах Ollama». Тогда Лира добавляет в запрос выбранные факты, учитывая пересечение слов с вопросом и свежесть записей (до 20, не больше 4800 знаков), а также последние сообщения. В демо на вопросы возвращаются совпавшие записи, а не свободный ответ модели.
- Передача отдельного блока памяти в Ollama и в совместимый API по умолчанию выключена до вашего разрешения. Оба переключателя находятся в окне памяти. Сам текст разговора обрабатывается выбранным провайдером как раньше. Отключение запоминания также отключает дополнительный контекст, но не стирает базу и историю.
- **Обновление с 2.4–2.8:** в том же браузере и по тому же адресу нажмите «Перенести старую память». После подтверждения имена, подробности старых карточек и заметки преобразуются в текстовые факты. Перенос добровольный, повтор не дублирует одинаковые записи. Исходные данные остаются в браузере, а активные напоминания продолжают работать без переноса. Очистка новой памяти не удаляет старые локальные копии.
- Ключ профиля хранится в localStorage браузера. Иной браузер/адрес получает отдельную память. Не очищайте данные сайта, если хотите сохранить доступ к прежнему профилю. Делайте резервную копию `data/memory.db` при остановленном сервере и сохраняйте тот же профиль браузера. База не шифруется; не публикуйте папку `data/`. Не используйте приложение как общедоступный многопользовательский сервис без отдельной авторизации и HTTPS.

## Напоминания, часы и погода

«Напомни завтра в 21:00 попить воды» создаёт напоминание с датой, а не факт. Сроки и «который час» используют локальные часы устройства. Срабатывание видно в открытой Лире, пропущенные дела отображаются при возвращении. Для прогноза скажите «Погода завтра в Казани» или задайте город в настройках памяти. Используются Open-Meteo и геокодирование GeoNames, нужен интернет: https://open-meteo.com/en/terms. Фильтры микрофона и проверка распознанного текста перед отправкой сохранены из версии 2.8.

## Разговор и перебивание

- **Зажмите пробел** вне текстового поля или **удерживайте кнопку микрофона**. Разрешите доступ при первом обращении. **Отпустите**, чтобы завершить ввод и отправить распознанную фразу.
- Так же можно перебить Лиру: новое нажатие сразу глушит её голос, сбрасывает ожидание предыдущего ответа и начинает слушать. Запоздавшие ответы не озвучиваются и не добавляются в историю; внешний сервер может закончить уже запущенное вычисление. Это ручное перебивание, не постоянно включённый микрофон.
- Потеря фокуса прекращает запись без отправки. При 60 секундах ввод завершается автоматически. В настройках доступно управление кнопкой по нажатию вместо удержания. Пробел вне полей ввода по-прежнему работает по удержанию.
- По умолчанию голос распознаёт **Vosk на устройстве**. Библиотека и русская модель входят в архив; отдельной установки, API-ключа и облачного сервиса для распознавания не нужно. При первом нажатии браузер загружает модель (~45 МБ) с сервера Лиры, затем кэширует её. В локальном режиме этот сервер — ваш компьютер. Пока модель готовится, полученные с микрофона фрагменты временно буферизуются в памяти. Микрофон выключается при отпускании. Не закрывайте страницу до завершения первой загрузки.
- Для микрофона откройте `http://localhost:8000` или HTTPS и разрешите доступ. Если микрофон заблокирован в предпросмотре, откройте приложение отдельной вкладкой. В настройках можно явно выбрать прежний «Сервис браузера»; он может использовать интернет и выдавать сетевые ошибки. Озвучка отделена от Vosk: по умолчанию выбран нейроголос Silero, системные голоса остаются доступны.


## Встроенные голоса и мимика

Откройте **Настройки → Голос персонажа**, выберите один из пяти русских голосов Silero (`xenia`, `kseniya`, `baya`, `aidar`, `eugene`) и нажмите **Послушать голос**. Короткая общая фраза и фиксированные демореплики уже записаны всеми пятью голосами в `assets/speech/` и воспроизводятся без установки синтезатора. Темп регулируется отдельно. Можно оставить системный голос ОС.

Для **произвольных ответов**, включая ответы Ollama, на компьютере с сервером нужен PyTorch. Рекомендуется 64-битный Python 3.11–3.13. Для Windows/Linux с CPU установите в том же окружении:

```sh
python -m pip install numpy
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

Для macOS: `python3 -m pip install torch numpy`. Размер PyTorch зависит от платформы. Перезапустите `python server.py`. При первом синтезе новой фразы сервер скачает общий для пяти голосов пакет `v4_ru.pt` (~40 МБ) с официального сайта Silero, проверит SHA-256 и сохранит в `~/.cache/lyra/tts`. Для загрузки нужен интернет, дальнейший синтез работает на CPU без внешнего голосового API. Если отсутствует синтезатор или сеть для первого скачивания, приложение сообщит об этом и попробует системную озвучку. В опубликованном предпросмотре синтез выполняется на сервере приложения; при локальном запуске текст остаётся на вашем компьютере. Первый ответ может готовиться дольше.

**Рот:** область раскрытия рассчитывается по уголкам губ и текстуре снимка. Зубы затенены верхней губой, нижний ряд слегка виден при более широком раскрытии. Когда рот закрыт, выводится исходное фото. Для нейроголосов амплитуда звука управляет раскрытием челюсти; это не точная фонемная анимация. Для системных голосов используется ритмическая анимация. Ползунок **Видимость зубов при речи** позволяет ослабить эффект для конкретного фото или убрать его. Проба голоса показывает крупный план лица прямо в настройках. Сохраните настройки для следующих разговоров.

Модель: [Silero Models](https://github.com/snakers4/silero-models), русский TTS v4, лицензия модели CC BY-NC 4.0 (для коммерческого использования проверьте условия правообладателя). Пакет весов не включён в архив. Готовые демореплики сгенерированы этой моделью, без клонирования голосов по портрету.

## Три режима диалога

**Демо.** Начальный режим, доступен сразу.

**Ollama.** Установите и запустите Ollama на компьютере с сервером Лиры. Загрузите модель, например `ollama pull qwen2.5:3b`. В настройках выберите Ollama → «Получить список моделей» → нужный ID → «Сохранить». Для другого адреса сервера задайте `OLLAMA_URL` до запуска Python. По умолчанию `http://127.0.0.1:11434`.

**LM Studio.** Загрузите модель с поддержкой чата, включите Local Server на порту 1234. В Лире выберите «LM Studio / OpenAI-совместимый API», запросите список моделей или введите ID вручную. Сервер Лиры по умолчанию использует `http://127.0.0.1:1234/v1`.

**Другой совместимый API.** Используется тот же режим, но перед запуском Лиры задайте `LLM_BASE_URL` (полный базовый URL API, обычно с `/v1`) и, если требуется, `LLM_API_KEY`. Ключ читается из окружения сервера — в браузере он не хранится. Пример для PowerShell:

```powershell
$env:LLM_BASE_URL = 'https://api.openai.com/v1'
$env:LLM_API_KEY = Read-Host 'Введите ключ API' -MaskInput
py server.py
```

`-MaskInput` поддерживается PowerShell 7.1+. В других оболочках используйте их средства управления переменными окружения. Для macOS/Linux (bash):

```bash
export LLM_BASE_URL='https://api.openai.com/v1'
read -rsp 'API key: ' LLM_API_KEY; echo; export LLM_API_KEY
python3 server.py
```

Нужна модель, совместимая с `POST /chat/completions`. Список использует `GET /models`, но ID можно указать и без него. Облачному провайдеру передаются до 18 последних сообщений, не фото; возможно платное использование. Адреса и доступность моделей зависят от провайдера. В предпросмотре сервер не видит модели на вашем компьютере. Для личного сервера с ключом оставьте привязку к 127.0.0.1: приложение не предусматривает авторизацию пользователей.

## Фон комнаты

Нажмите **Фон** в правом верхнем углу сцены. Доступны «Сумерки в горах», «Туманный лес», «Вечерний интерьер» и «Градиент». Можно загрузить свой JPG, PNG или WebP до 12 МБ. Широкие горизонтальные изображения лучше всего заполняют сцену. Пользовательский фон подготавливается в браузере, не отправляется на сервер и не записывается в файлы проекта. Выбор сохраняется при перезагрузке. Кнопка «Удалить свой фон» удаляет его локальную копию. Фон сцены независим от аватара. Если загруженный портрет непрозрачный, его собственный фон внутри изображения останется видимым: для полной замены включите удаление фона в студии портрета или используйте прозрачный WebP/PNG.

## Публикация исходников

В репозиторий помещайте **содержимое архива исходников** рядом с `.git/`, включая `assets/` и `licenses/`. Пользовательские файлы, личные настройки, история и кэши не входят в сборку. Встроен один персонаж — Лира. Три пейзажных/интерьерных фона созданы для проекта, градиент нарисован в CSS. При публикации убедитесь, что у вас есть права на используемый портрет, сохраняйте атрибуции сторонних компонентов и учитывайте некоммерческие условия модели Silero. Файл модели Vosk (~45 МБ) уже включён: для публикации большого файла используйте Git, а не загрузку отдельных файлов через веб-форму. Для полноценной работы нужен Python-сервер; статический хостинг сам не запустит серверные API чата и синтеза речи.

## Оживить другой портрет

1. В настройках откройте **Аватар → Изменить → Выбрать фото**. Подходит своё фото или портрет человека с его согласия. Используйте чёткий снимок анфас с хорошим светом, открытыми глазами и сомкнутыми губами, желательно с плечами в кадре. JPG, PNG, WebP, до 12 МБ.
2. Посмотрите результат на шахматном фоне. «Убрать однотонный фон» удаляет цвет, связанный с краями изображения. Допуск можно уменьшить, если исчезают детали одежды, или увеличить, если остаётся светлая кайма. Это не нейросетевая сегментация сложных сцен. Имеющаяся прозрачность сохраняется. **Скачать WebP** работает и без разметки: качество кодирования 98%, размер исходника до 2560 px по длинной стороне. WebP сам по себе не восстанавливает отсутствующие детали.
3. Укажите четыре точки по подсказкам: центр зрачка слева и справа **на изображении**, затем левый и правый уголки рта. «Шаг назад» исправляет предыдущую отметку.
4. Нажмите **Применить**. Портрет выравнивается по глазам. Он моргает, переводит взгляд, наклоняется при прослушивании и двигает губами во время озвучки. Языковая модель и голос не меняются. В этой же студии можно вернуть портрет Лиры.

Фото обрабатывается на устройстве. Новые пользовательские текстуры подготавливаются в 1152×1536 и сохраняются в WebP с прозрачностью, а не повторно в JPEG. Подготовленный портрет и точки хранятся в localStorage этого браузера. Восстановление исходного аватара удаляет сохранённую замену. История удаляется отдельно через «История». Это процедурная 2D-анимация, а не нейросетевая реконструкция лица: нет поворота в профиль, точных фонем или клонирования голоса. На нестандартных ракурсах результат хуже. Системная настройка уменьшенного движения отключает покачивания и слежение взглядом.

## Файлы

`server.py` — статический интерфейс и адаптеры провайдеров; `voice.js` — push to talk; `avatar.js` — анимация; `photo.js` — загрузка и разметка; `app.js` — диалог, настройки и озвучка; `assets/` — исходный аватар, спрайты и фон. Проверка адаптеров без внешних сервисов: `python -m unittest discover -s tests`. Модули: папка `modules/` и `modules-ui.js`; вахтёр — `modules/vakhta/`; тесты модуля — `node --test tests/vakhta.test.js`.
